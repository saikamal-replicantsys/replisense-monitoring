## RS-1143: dashboard story

Stable dashboard UID/URL: `replisense-qc-operations`; folder and existing panel
IDs are preserved. Edit `scripts/build_dashboard.py`, not generated JSON.

1. **At a glance:** large live Customer access, QC processing health and
   Monitoring coverage cards; selected-period completed reviews, generated
   DOCX files, failed attempts and API errors.
2. **Needs attention / review activity:** prominent current alerts, availability
   history and a review-duration heatmap built from existing histogram buckets.
3. **Performance:** requests and 95th-percentile response/processing times,
   using plain-language titles and explanatory descriptions.
4. **AI usage:** actual provider labels, not the outdated Gemini-only headings.
   Zero-only preinitialized providers are hidden. Input/output token counts
   avoid mixing overlapping total/cache counts. This is not a provider bill.
5. **Technical details:** smaller dependency/metrics checks, CPU/memory,
   certificate expiry and heartbeat, followed by sanitized operational logs.

Health cards use instant queries and expected target counts. Missing telemetry
is never Healthy. Event/error counters show zero only when their producer is
reporting successfully and recently. Durations with no measured observations
are omitted rather than shown as zero-second processing. Counts are sampled
Prometheus estimates, not MongoDB totals, quotas or unique documents. Failed
attempts are not permanently failed documents; exports are not downloads.

Refresh is 60 seconds, matching the collector scrape interval and reducing
unnecessary hosted queries. Existing telemetry privacy rules remain intact.
Telemetry freshness is displayed separately from target coverage. A dependency
graph combines live health readings with configured architectural links: its
arrows are not measured traffic or traces. Incident panels link to alerts and
the runbook. Deployment annotations use the existing Grafana annotation store;
the optional local deployment helper records only QC component names, immutable
commit IDs and completion time. No new server process or collector is required.
Alert thresholds, notification routing and application retry behavior do not
change. The old Gemini-specific provider alert is given a provider-neutral title
and description; its historical UID and already-provider-neutral query remain
unchanged. The current-alert list is restricted to QC and excludes setup tests.
